peer-contract v0.1

agent 之间的通用通信协议。5 份 JSON Schema，零依赖 CLI，OpenClaw 插件以 enforce 模式运行，enforce 9 条硬规则。

v0.1.0 MIT 166/166 tests 5/7 e2e PASS + 2/7 e2e BLOCK（符合设计） OpenClaw 0.7.1+
战略目的

当 agent（LLM 驱动或其他）互相委派工作时，没有契约层会导致三个问题：隐式路由、上下文泄漏、责任链断裂。peer-contract v0.1 用显式路由（HR1）、自包含 payload（HR4）、不可变验收标准（HR7）、追加式审计日志（HR5）解决所有三个。OpenClaw 插件在 enforce 模式运行时 enforce 9 条硬规则，包含 intent-aware 的 HR1 和跨 agent 到 work 的 block，符合战略设计意图。

三个核心问题

1
隐式路由

工作派到了错误的 session（通常是协调者的 main），因为调度者必须猜 target。

2
上下文泄漏

接收方继承过多或过少的状态，导致反应过激或不足。

3
无责任链

没有谁派了什么、用什么 AC 的审计记录，责任链断裂。

协议一次解决三个

✓
显式 target_session_key

每个 dispatch 携带 target。HR1 (no-default-to-main) 拦隐式路由。

✓
自包含 payload

显式 context_scope + HR4。没有"查一下"这种隐式引用。

✓
AC 不可变 + 审计

HR7 锁住验收标准，worker 不能改。HR5 跨 session query 必写 audit log。

跨 agent 对话和 bus/work 分离

每个 agent 有一个 public bus 边界 + 一个 private work sub-session。协议 enforce 两种 layout：跨 agent dispatch 走 bus↔bus（ALLOW），任何跨 agent 直接到 work 被 HR1 BLOCK。

两个 agent 之间的 dispatch：bus↔work session 模型
sequenceDiagram
    participant Ab as A.bus
    participant Aw as A.work
    participant Bb as B.bus
    participant Bw as B.work

    Note over Ab,Bw: Phase 1 — 跨 agent dispatch 走 bus↔bus（HR1 ALLOW）
    Ab->>Bb: dispatch (target=B.bus, payload=v0.1)
    Bb->>Bw: intra-agent sub-session spawn
    Bw->>Bw: 执行任务
    Bw-->>Bb: yield_report
    Bb-->>Ab: 返回结果

    Note over Ab,Bw: Phase 2 — 跨 agent 直接到 work 是 anti-pattern（HR1 BLOCK）
    Ab-->>Bw: ✗ dispatch 到 B.work（跨 agent 到 work）
    Aw-->>Bb: ✗ 从 A.work dispatch 到 B.bus（跨 agent 到 work）
    Aw-->>Bw: ✗ 从 A.work dispatch 到 B.work（跨 agent 到 work）

仓库结构

公开协议 — dispatch、isolation、multi-turn、bus、envelope。Platform-agnostic。

零依赖 CLI

Node.js，无 ajv/zod。4 个子命令：check、validate-schema、ac-chain、dry-run。

OpenClaw 插件

12 src + 10 test 文件。在运行时 enforce HR1/HR5/HR6（enforce 模式）。

scenarios/
2 个 YAML

端到端 dry-run 场景：basic dispatch + multi-turn AC chain。

docs/
8 篇维护文档

architecture、maintainability、known-limitations、post-install-procedures + 4 篇设计 notes。
